# Debugging in Cross-Platform Development

## Overview

Debugging is essential for identifying and resolving issues across iOS and Android in React Native apps. Tools like **console logging**, **Chrome DevTools**, **Visual Studio Code**, and **Flipper** offer consistent and powerful ways to debug cross-platform code. Incorporating both runtime and build-time strategies helps maintain code quality and performance across platforms.

---

## Logging

### Console Logging

* Use for basic runtime information and quick debugging.
* Example:

  ```javascript
  console.log('App initialized');
  console.warn('Deprecation warning');
  console.error('Something went wrong');
  ```
* ⚠️ **Important**: Remove or conditionally disable logs in production builds to improve performance and security.

### `react-native-logs`

* Advanced logging with support for levels, namespaces, colors, and transports.
* Example:

  ```javascript
  import { logger } from 'react-native-logs';
  const log = logger.createLogger();
  log.debug('Debug message');
  ```

### File Logging

* Persist logs to files using `fileAsyncTransport` (for crash reproduction, analytics, etc.).
* Example:

  ```javascript
  import { logger, fileAsyncTransport } from 'react-native-logs';
  import RNFS from 'react-native-fs';

  const config = {
    transport: fileAsyncTransport,
    transportOptions: { FS: RNFS, fileName: 'debug-log.txt' },
  };
  const log = logger.createLogger(config);
  log.debug('Log written to file');
  ```

## Chrome Debugging

* Enable **"Debug JS Remotely"** from the in-app developer menu (⌘D on iOS / ⌘M or Ctrl+M on Android).
* Chrome DevTools opens at:
  `http://localhost:8081/debugger-ui`
* Features:

  * Inspect variables, network requests, and logs.
  * Set breakpoints and watch expressions.
* ⚠️ Works by proxying JS execution to Chrome (not running on device).

## Visual Studio Code (VS Code) Debugging

### Setup

* Install **React Native Tools Extension** by Microsoft.

### Example `launch.json` Configuration:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug Android",
      "type": "reactnative",
      "request": "launch",
      "platform": "android"
    },
    {
      "name": "Debug iOS",
      "type": "reactnative",
      "request": "launch",
      "platform": "ios"
    }
  ]
}
```

* Set breakpoints in VS Code.
* Attach debugger or launch from within the IDE.
* Debug directly in the simulator/emulator.

## Flipper (Recommended for Native Debugging)

* A platform by Meta for debugging React Native, native Android/iOS code, performance, layout, and network traffic.

### Setup:

* For bare React Native projects:

  ```bash
  npm install --save-dev react-native-flipper
  ```

### Features:

* Network Inspector
* Layout Inspector
* Logs Viewer
* React DevTools
* Hermes Inspector

> Requires native configuration in `android/app/build.gradle` and iOS `Podfile`.

---

## Hermes Debugging Support

* Hermes is a lightweight JS engine used in React Native for performance.
* Works with:

  * Chrome DevTools (via `DebuggerWorker.js`)
  * Hermes Inspector (in Flipper)

Enable Hermes in `android/app/build.gradle`:

```gradle
hermesEnabled: true
```

## Error Handling Strategies

### Error Boundaries (for UI crashes)

```javascript
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  componentDidCatch(error, info) {
    console.error(error, info);
  }
  render() {
    if (this.state.hasError) return <Text>Something went wrong</Text>;
    return this.props.children;
  }
}
```

### Global Error Handlers

* Catch unexpected errors or uncaught promise rejections:

```javascript
import { setJSExceptionHandler } from 'react-native-exception-handler';

setJSExceptionHandler((error, isFatal) => {
  console.log('Global error caught:', error);
}, true);
```

## Cross-Platform Best Practices

| Technique             | iOS | Android | Notes                                                 |
| --------------------- | --- | ------- | ----------------------------------------------------- |
| Console logs          | ✅   | ✅       | Use `console.log`, `warn`, `error` for fast feedback  |
| Chrome debugger       | ✅   | ✅       | JS is debugged in Chrome context (not on-device)      |
| Flipper               | ✅   | ✅       | Best for native debugging, layout, network            |
| VS Code with RN tools | ✅   | ✅       | Breakpoint support, live reload, attach to simulators |
| Error boundaries      | ✅   | ✅       | Prevent app crash on component errors                 |
| Global error handling | ✅   | ✅       | Capture runtime and async errors in production logs   |

## Debugging Tips

* Use `Platform.OS` to isolate platform-specific bugs:

  ```javascript
  if (Platform.OS === 'android') log.warn('Android-only issue');
  ```
* Use **Redux DevTools** or **React DevTools** with Flipper or Chrome.
* Clear Metro bundler cache:

  ```bash
  npx react-native start --reset-cache
  ```
* Always test on both **real devices** and **simulators/emulators**.

---

## Conclusion

Effective debugging in React Native ensures a stable experience across Android and iOS. By using a combination of **console logs**, **Flipper**, **VS Code**, and **global error handling**, you can identify issues early, streamline testing, and improve app reliability. Debugging cross-platform apps doesn't have to be complex—with the right tools, it becomes a smooth part of development.
