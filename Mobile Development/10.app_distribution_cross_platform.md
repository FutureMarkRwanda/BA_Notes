# App Distribution in Cross-Platform Development

## Overview

Distributing React Native apps to app stores involves preparing platform-specific builds, signing them, and submitting them through official portals. Tools like **Expo**, **EAS (Expo Application Services)**, and **CodePush** make cross-platform deployment easier, especially when maintaining a single codebase for both iOS and Android.

---

## Building for Android

### Using React Native CLI

1. **Generate a signing key**:

   ```bash
   keytool -genkey -v -keystore my-release-key.keystore -alias my-key-alias \
   -keyalg RSA -keysize 2048 -validity 10000
   ```

   Place it in `android/app` and update `gradle.properties` and `build.gradle`.

2. **Build APK or AAB**:

   ```bash
   cd android && ./gradlew assembleRelease   # for APK
   ./gradlew bundleRelease                   # for AAB (recommended)
   ```

3. **Output Location**:

   * APK: `android/app/build/outputs/apk/release/app-release.apk`
   * AAB: `android/app/build/outputs/bundle/release/app-release.aab`

### Using Expo (Recommended)

1. **Install EAS CLI**:

   ```bash
   npm install -g eas-cli
   ```

2. **Build Android App**:

   ```bash
   eas build -p android --profile production
   ```

   Select **AAB** for Google Play submission (preferred format since 2021).

---

## Building for iOS

### Using Expo

1. **Build iOS App**:

   ```bash
   eas build -p ios --profile production
   ```

2. **Submit via App Store Connect**:

   * Use `eas submit -p ios` (automates upload), or
   * Download `.ipa` and upload via **Transporter App** (macOS only).

3. **Test with TestFlight**:

   * Distribute beta versions before public release.

> Note: A Mac with Xcode is required for native builds unless you're using Expo Cloud Build.

## Over-the-Air (OTA) Updates

### Using CodePush (for bare React Native)

* CodePush enables JS/asset updates without requiring a new app store submission.

```javascript
import codePush from 'react-native-code-push';
const App = () => { /* your component */ };
export default codePush(App);
```

### Using Expo OTA (Managed Workflow)

* Every `expo publish` pushes a JS bundle update.
* Users get updates the next time the app launches or as configured.

```bash
expo publish
```

## App Store Submission Process

### Google Play Store

* Register a **Google Play Console** account.
* Upload **.aab** file to your app release page.
* Fill in details: content rating, privacy policy, assets, app signing.
* Use:

  ```bash
  eas submit -p android
  ```

### Apple App Store

* Register an **Apple Developer Account** (\$99/year).
* Create App ID, provisioning profiles, and certificates.
* Upload using `eas submit -p ios` or Apple Transporter.
* Complete App Store Connect metadata: screenshots, privacy, review notes.

## Versioning and Configuration

Update your `app.json` or `app.config.js`:

```json
{
  "expo": {
    "version": "1.0.0",
    "android": {
      "versionCode": 1
    },
    "ios": {
      "buildNumber": "1.0.0"
    }
  }
}
```

## Cross-Platform Benefits

| Tool/Feature        | Android | iOS | Benefit                                                     |
| ------------------- | ------- | --- | ----------------------------------------------------------- |
| **Expo & EAS**      | ✅       | ✅   | Unified workflow for building and deploying apps            |
| **CodePush / OTA**  | ✅       | ✅   | Push updates without app store resubmission                 |
| **TestFlight**      | ❌       | ✅   | Beta testing before public launch                           |
| **Play Console**    | ✅       | ❌   | Native platform for Android publishing                      |
| **Single Codebase** | ✅       | ✅   | Easier maintenance and consistent features across platforms |

## Best Practices

| Practice                                      | Reason                                           |
| --------------------------------------------- | ------------------------------------------------ |
| Use **AAB** for Android                       | Required by Google for new apps                  |
| Follow Apple’s **Human Interface Guidelines** | Prevent app rejection on iOS                     |
| Sign your builds securely                     | Protects users and prevents tampering            |
| Use **versioning** properly                   | Helps with OTA updates and store compliance      |
| Test on real devices and emulators            | Catch platform-specific issues before submission |
| Automate builds and releases (CI/CD)          | Speeds up deployment and reduces human error     |

---

## Conclusion

App distribution in cross-platform development involves both common practices and platform-specific steps. Using modern tools like **EAS**, **CodePush**, and **OTA updates**, developers can streamline builds, testing, and publishing. Whether you're deploying to Google Play or the Apple App Store, keeping your pipeline secure, efficient, and well-documented is key to success.
